# 逆向过程回顾

记录这套方案是怎么一步步做出来的，主要是给后来者省时间。全程只针对自有设备。

## 0. 先判断从哪一侧下手

两条路：

- **改 App**：把 App 的服务器地址指向本地。缺点是 App 更新就废，而且换手机就得重做。
- **改设备**：在路由器上把设备的出站流量接管。不碰 App、不碰设备，一次配置长期有效。

选后者。前提是设备真的会主动出连（IoT 设备基本都会）。

## 1. 找到设备在连谁

路由器上 `conntrack -L | grep <设备 IP>`，看到一条长连接：

```
tcp ESTABLISHED src=192.168.31.100 dst=47.x.x.x dport=1883
```

`1883` 就是 MQTT。目标 IP 会变（阿里云负载均衡），所以**不要按目的 IP 做规则**。

## 2. 尝试用 mitmproxy 代理，失败

第一反应是 `--mode reverse:tcp://<云IP>:1883`，结果握手失败：

```
NO_SHARED_CIPHER
```

抓设备 ClientHello 才发现它只提供 4 个套件，全是 **RSA 密钥交换**：

```
003d 0035 003c 002f 00ff
```

而中间 CA 是 ECDSA 的（`EM OV TLS CA - G3C`），无法签发 RSA 证书给它。这条路走不通。

## 3. 换思路：设备根本不校验证书

那就自己签一张 RSA 证书（CN 用官方域名），让 broker 直接终结 TLS：

```
openssl req -x509 -newkey rsa:2048 ... -subj "/CN=public.iot-as-mqtt.cn-shanghai.aliyuncs.com"
```

Go 里必须加 `//go:debug tlsrsakex=1`（Go 1.22+ 默认禁用 RSA 密钥交换），
CipherSuites 只列那 4 个。握手立刻成功，MQTT CONNECT 明文到手。

**这是整个方案的关键发现：设备不校验证书。**

## 4. 抓包路上的坑

- **路由器 hnat/flowtable 会绕过 iptables 和 tcpdump**：在 `FORWARD` 加 REJECT 依然能通，
  tcpdump 抓不到包。解决办法是 DNAT 到 `127.0.0.1`（走 INPUT，不经过转发路径）。
- **DNAT 到 127.0.0.1 需要 `route_localnet=1`**，否则内核按 martian 丢弃。
- **conntrack 会保留旧连接**：加完规则后设备仍连公网，要 `conntrack -D -s <ip> -p tcp --dport 1883`
  逼它重连。

## 5. 拿状态字段

先抓一份完整快照（93 字节），再把每个 TLV 和 App 界面对照。做法是**改变物理状态**，看哪个字节动：

| 动作 | 变化的字段 |
|---|---|
| 打开/关上盖 | `0x16` 取反 |
| 抽出/放回集便盒 | `0x17` 取反 |
| 集便盒装满 | `0x18=01` |
| 猫进出 | `0x04` |
| 猫上完厕所 | `0x09`（体重 + 时长） |
| 手动清理 | `0x11` 00→01→02 |
| 双击 Reset | `0x11` 05→06，伴 `0x0d`/`0x0b` |
| 打开 App 设置页拨开关 | 对应 `0x02/0x05/0x06/0x07/0x14/0x15` |

`0x65` 一开始把所有时间字段都算错了：完整帧里它是**秒偏移字符串**（`"28800"`），
只有使用记录帧里才是 `YYYY-MM-DD HH:MM:SS N`。判断条件是**有没有冒号**。

## 6. 下发命令

把 App 上的每个操作都点一遍，记录 broker 看到的 `down_raw`，然后逐条回放验证。
`01 01 01` / `01 01 03` / `01 01 04` 分别是清理 / 倒空 / 平砂——注意
**清理（Clean）不换袋，倒空（Dump）要换袋**，说明书里写得很清楚，别搞混。

## 7. 设备重启后的两个必答题

- **NTP**：设备会发 `/ext/ntp/<pk>/<dn>/request`，不回就一直重发，时间也全错。
- **443**：设备会连 `*.link.aliyuncs.com:443` 做激活/OTA 检查。**只 REJECT 会让它卡在开机状态**，
  实测重试十几分钟都不打开 MQTT。必须给它一个能返回 200 的 HTTPS 服务。

这两点是"看起来能跑"和"长期稳定"的分界线。

## 工具清单

| 用途 | 工具 |
|---|---|
| 看设备连谁 | `conntrack` |
| 抓包（htnat 不干扰时） | `tcpdump -i br-lan` |
| 解 TLS | 自签 RSA 证书 + Go `tlsrsakex=1` |
| 解析 MQTT 帧 | 一个几十行的 Python 脚本即可（QoS 0，无 SUBSCRIBE） |
| 对照状态 | 手机上的官方 App + 物理动作 |
